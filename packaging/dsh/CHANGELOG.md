- **修复「打开 3080 只有一句 dsh web authentication required」**：浏览器里残留的旧 `dsh-auth-*` cookie 会遮蔽 runner 自签的那份 —— dsh 解析 cookie 时只取**同名 cookie 的第一个**，而 runner 签发的是追加在后面的，于是旧值生效、一律 401。现在转发前先剔除浏览器带来的所有 `dsh-auth-*`（其它 cookie 原样保留），WebSocket 握手同理；401 回退官方令牌的重试也从「仅导航请求」放宽到所有 `GET`。
- **修复「安装/卸载插件报 origin not trusted」**：dsh 的 `/api` 有一道 browser-trust 围栏 —— 请求带 `Origin` 时必须与 `Host` 同源，否则 403。以前 dsh 自己对外监听 3081、浏览器在另一个 authority 上，所有跨源 POST 都被拦。现在改成**单入口反向代理**：`dsh web` 只监听 `127.0.0.1:3081`（`--host 127.0.0.1`，外部不可直连），`runner/runner.js` 在 `0.0.0.0:3080` 上代理 HTTP 与 WebSocket，转发时把 `Host` 改写为回环 authority、剥掉 `Origin`/`Referer` —— 围栏按「回环 Host、无 Origin」放行，插件安装、插件市场、内置终端全部可用。
- **去掉启动令牌，浏览器不再需要 `?token=`**：runner 直接用 `.credentials.yaml` 里的 `client-connection/browser-session` secret 自签 dsh 会话 cookie 注入上游，并把上游的 `Set-Cookie` 从响应里剥掉。好处：飞牛桌面入口的静态 URL 直接可用；浏览器侧不持有绑定 3081 的 cookie；**重启后不会再 401**。自签若因上游改格式失效，自动回退到官方「启动令牌换 cookie」。
- **不再绑定局域网 IP**：`--host` 固定 `127.0.0.1`，本机与局域网都经 3080 进。NAS 换 IP 后不再需要重启应用，「NAS 本机打不开」也一并消失。
- **进程看护**：`dsh web` 退出一秒内由 runner 重启；`cmd/main` 的看门狗只在 runner 整个进程意外死亡时兜底。原 gate 与 `launch-token` 机制整体删除。
- **跟紧官方发布节奏（按发布时间最新跟随）**：上游同时维护两条线（`0.2.1-rc.N` 稳定线与 `0.2.2-alpha.N` 预览线），并会把稳定线的补丁作为**新发布**推出来 —— `0.2.1-rc.5`（10-30）就比 `0.2.2-alpha.2`（10-28）更晚，npm 的 `latest`/`next` 都指向 rc.5。以前按「版本号看起来最高」取版本，会一直停在预览线上、错过官方当前在推的稳定版；现在按**发布时间最新**跟随，官方发哪个就跟哪个。
  - 版本号不会因此倒退：`scripts/next-version.mjs` 保证发布版本**单调递增**。上游数字段低于历史高水位时，顺着高水位末段 +1（`0.2.2-alpha.2.1` → `0.2.2-alpha.2.2`）；同一上游版本重发也是 +1（`0.2.2-alpha.2` → `0.2.2-alpha.2.1`）。两者都用上游不会发出的号，永不与上游将来版本撞车。
  - `build/dsh/highest-version.txt` 是高水位，只增不减 —— 即使旧 Release 被清理、索引被写坏，也不会再发布一个更低的版本（这正是之前「应用中心不提示更新、也不显示更新内容」的根因：索引被从 `0.2.2-alpha.2` 写回 `0.2.1-rc.5`，飞牛只比数字段 `0.2.1.5 < 0.2.2.2`，判定"没有更新"）。
  - 更新说明顶部会标注本次实际同步的上游版本，与版本号后缀区分开，避免「版本号看着像 alpha 线、内容其实是稳定线」的困惑。
- **修复「点开 DSH 卡片打不开网页」**：`dsh web` 长时间运行会堆内存耗尽退出（日志 `Reached heap limit`，约 2 GB），而 gate 仍在 3080 上把浏览器 302 到已经没人监听的 3081，浏览器报「无法访问此网站」。
  - 新增看门狗：每 10 秒检查 dsh 进程，退出即按同样参数重启并刷新启动令牌（gate 每次请求重读 `launch-token`，不必重启 gate）；连续失败退避到最多 5 分钟。`stop` 时先杀看门狗，避免刚停掉又被拉起。
  - gate 在换 cookie 之前探测 dsh 端口，不通就返回 503「DSH 正在重启」，不再把浏览器送到死端口。
- **修复重启后必定 401**：`wait_token` 原先从整个日志 grep 启动令牌，而日志是跨重启追加的 —— 重启后 dsh 还没打印新令牌，第一轮循环就命中上一轮的旧令牌。改为 spawn 前记录日志字节偏移，只扫描本次启动之后新增的部分。
- **修复「安装包大小校验失败」**：同一版本的 Release 资产以前是**原地覆盖**，而 fpk 每次构建的字节都不同，于是索引里记的大小/sha256 与线上文件对不上，飞牛安装时直接报 `expected=… actual=…`。现在产物名带内容指纹（sha256 前 12 位，如 `DSH_v0.2.2-alpha.2_amd64_8c0f1e407cba.fpk`），下载地址与内容绑定、永不改变；索引切换是原子提交，旧资产保留 1 小时后自动清理。
- **支持在 NAS 本机上访问**：dsh 只绑局域网 IP，`127.0.0.1` 上原本没人监听，在 NAS 本机开浏览器打不开。gate 现在额外监听 `127.0.0.1`，用 `http://127.0.0.1:3080` 即可（`localhost` 可能解析到 `::1`，不要用）。
- **地址栏不再跳到 3081（gate 改为反向代理）**：以前从 3080 进入会被 302 甩到 `:3081`，地址栏变端口、书签和反向代理都不好用。现在 3080 直接反向代理 dsh：首次进入时用启动令牌在服务端换 cookie、303 回原地址，之后所有请求（含 WebSocket）原样转发，地址栏始终停在 3080。转发时把 `Host`/`Origin` 改写成 dsh 的 authority，否则它的会话 cookie 与 `/api` 围栏会一律拒绝。
- **日志只留异常**：gate 只在启动、监听失败、令牌兑换失败时记一行，不再逐条记录访问。
- **修复「上传图片/文件失败」**：dsh 0.2.2 起，附件落盘前会把 `<DSH_HOME>` 的每一级祖先目录都打开 fsync 一遍（`dsh-attachment-local` 的 `ensureDurableHome`）。飞牛上 `/vol1` 与 `/vol1/@appshare` 对应用用户不可读（只对应用自己的目录放行），这一步直接 `EACCES`，于是上传报 `failed to store file upload: Error: EACCES: permission denied, open '/vol1/@appshare'`。祖先目录的 durability（崩溃后目录项是否已落盘）不是应用能负责的，打包时对该步骤放宽 `EACCES/EPERM/EROFS`，其余错误照旧抛出。
